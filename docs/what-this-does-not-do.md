# このツールがしないこと

ssm-fleet-toolkit が**やらないこと**を明示します。やらないことを明確にすることで、利用者の安心と運用の単純さを担保します。

## サーバーへの変更操作

- パッケージ更新、設定変更、サービス再起動などは行いません
- `documents/stateful/` ディレクトリは意図的に空です
- 将来 stateful Document を追加する場合も、別プレフィックス（`ops-modify-*`）で明確に分離します
- インストーラ・オペレータいずれの権限にも、サーバーへの書き込み権限は含まれません

## データの外部送信

- 取得したサーバー情報は SSM の標準ログ（同一 AWS アカウント内）に留まります
- 外部 API（Claude API を含む）にサーバー情報を直接送信しません
- Claude Code は利用者のローカル端末で動作し、サーバー上では動きません
- 取得結果を Claude が要約する場合も、要約処理は利用者の Claude Code 経由で行われます（送信先は Anthropic API のみ）

## 認証情報・秘密情報の収集

- パスワード、API キー、秘密鍵、証明書ファイル等を取得する Document はありません
- セキュリティ調査用の Document でも、設定の「存在確認」や「バージョン確認」のみで、ファイル本体は読みません
- `/etc/shadow`、`~/.ssh/`、`/etc/ssl/private/`、`/etc/aws/credentials` などへのアクセスは行いません

## 子アカウントへの侵襲

- StackSet で配布される IAM ロールは SSM Document 実行に必要な権限のみ
- 子アカウントの他リソース（EC2 設定変更、S3 バケット操作、RDS 操作等）への権限は含まれません
- 子アカウント側の運用には一切影響を与えません

## 既存 AWS リソースの変更・削除

- すべての作成リソースは `ssm-fleet-*` または `claude-investigate-*` プレフィックス
- 既存の他リソース（VPC、EC2、IAM ロール、S3 バケット等）には一切触れません
- 既存の SSO permission set は読み取りも書き込みもしません（このツール用の permission set のみ管理）
- `terraform plan` で常に `0 to change, 0 to destroy` を確認可能

## アカウント・ユーザーの作成

- AWS アカウントの作成・削除はしません
- IAM ユーザーの新規作成はしません（既存ユーザー・グループに permission set を割り当てるのみ）
- SSO のグループ作成・メンバー変更はしません（管理者が事前に作成したグループに割り当てる）

## CloudTrail / 監査ログへの干渉

- CloudTrail の設定変更・削除はしません
- 既存の監査ログ・通知設定には触れません
- このツールの操作はすべて通常通り CloudTrail に記録され、利用者が監査可能

## 課金構造の変更

- 高額な AWS サービス（GuardDuty、Macie、Inspector 等）の有効化はしません
- 既存の Cost Explorer 設定・予算アラートには触れません
- このツール自体のランニングコストは月額 $1 未満程度（S3 state + DynamoDB lock）

## ベンダーロックイン

- AWS SDK ベースで動作するため、AWS 環境であれば移植可能
- 利用者のリポジトリと state は利用者の AWS アカウント内に留まる
- このツールを削除しても、利用者の既存環境は元のまま
